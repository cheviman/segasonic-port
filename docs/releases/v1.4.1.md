The native port of Sega's 1993 arcade game *SegaSonic The Hedgehog*: not an emulator, but the game's own
program decompiled into C ([segasonic-decomp](https://github.com/cheviman/segasonic-decomp)) and built for
Windows, Linux and macOS, and, with its assets made on your computer, for the Nintendo Switch, Android and
Anbernic's handhelds.

**No game data is included.** You need your own MAME ROM set: `sonic.zip`, *SegaSonic The Hedgehog*
(Japan, rev. C). Put it beside the game, or drop it on the window the game opens the first time: the game
checks it and takes out what it uses, once.

| System | Package |
|---|---|
| Windows 10 or 11, x64 | `segasonic-windows-x64.zip` |
| Linux, x64 | `segasonic-linux-x64.tar.gz` |
| macOS 11 or later, Apple silicon and Intel | `segasonic-macos-universal.zip` |
| Nintendo Switch | made by `SegaSonic NSP`, in each package above |
| Android 7 or later | made by `SegaSonic APK`, in each package above |
| Anbernic's H700 handhelds, stock firmware | `segasonic-anbernic.zip` |

What is new since v1.4.0:

- **The stick's dead zone** ([#5](https://github.com/cheviman/segasonic-port/issues/5), an Xbox controller's
  drift): a game controller's left stick that rests a little off the middle no longer rolls Sonic, or the
  menus' cursor, on its own. The stick rolls nothing in its first 15% now, and from there out to all of STICK
  at the end of its travel. OPTIONS → TRACKBALL has DEAD ZONE beside STICK (0% to 50%), and the game's ini
  keeps it (`[controller]` `dead_zone`).
- **RecompLauncher**: the game installs, sets itself up and starts from
  [RecompLauncher](https://recomplauncher.com/game/segasonic-port). It asks for your `sonic.zip`, makes the
  game's assets on its setup screen, and shows the game's settings on its page (`recomplauncher.json`, in each
  computer package). From a command line, a script or a shortcut, `--game path/to/sonic.zip` (or a folder of
  its files) makes the assets from there with no window, and `--prepare` with it makes them and ends; without
  them the game starts as before.
- **Game controllers in games Steam starts**: Steam gives the games it starts its own controller mappings,
  which left out the ones the game carries (SDL_GameControllerDB's, and your `gamecontrollerdb.txt`). The game
  takes all of them now.

The Switch's `.nsp` and the Android APK are made again with this release's `SegaSonic NSP` and
`SegaSonic APK` (their `switch` and `android` folders hold the new game); an APK made with the same key
installs over the last one and keeps what the game wrote. What they make, and the Anbernic folder with your
pack in it, carries your ROM's assets: it is yours alone, never share it.

How it was checked: the dead zone with the stick's values through the game's own code (at rest up to 15%
nothing rolls, all the way the same 30 counts a frame as before), and its line in OPTIONS → TRACKBALL with the
console's headless build; `--prepare` and `--game` on Windows with a `sonic.zip` and with a folder of its
files, the assets the same, byte for byte, as the first run's. The README's pictures are the same as v1.4.0's
but TRACKBALL's, which has the new line. **Not tried yet on a device**: the reporter's Xbox controller (if it
still drifts, raise DEAD ZONE and tell us on #5), and the game set up from RecompLauncher itself.

SDL2 and the C runtime are built into the computers' executables: nothing else to install. The macOS apps
are not signed by a developer: the first time, open one with right click → Open (on macOS 15 and later, try
to open it, then System Settings → Privacy & Security → Open Anyway).
